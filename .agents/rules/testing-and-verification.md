# 테스트 및 품질 검증 규칙 (Testing & Verification)

## 1. 바이너리 변환 100% 동등성(Parity) 테스트 필수
`AtoJ`의 가장 중요한 핵심 요구사항은 변환된 `.DAT` 파일이 센터 단속처리 서버에서 오류 없이 처리되는 것이다.
- **단위 테스트 (`Vitest`)**:
  - 속도위반(`enf_code = '1'`) 및 신호위반(`enf_code = '3'`, 트래킹 프레임 포함) 샘플 아규격 바이너리를 생성하여 변환했을 때, 기존 Python `legacy_src/muin.py`가 생성한 `.DAT` 바이트 배열과 **단 1바이트의 오차도 없이 100% 일치하는지** 검증한다.
  - `CP949` 한글 차량번호(예: `12가3456`, `서울02라1234`, 미인식 `XXXXXXXXXXXX`) 인코딩 및 20바이트 `0x00` 패딩을 검증한다.
  - 아규격 파일명 정규식(`\d{16}\.[A-Z]\d{4}$`) 검증 및 비규격 파일 유입 시 설정된 정책(`ignore` / `quarantine` / `delete`)에 따라 안전하게 동작하는지 테스트한다.
  - 내장 JPEG 추출 시 7바이트 사이즈 헤더 및 `0xFF 0xD8` ~ `0xFF 0xD9` 마커 추출이 정확히 동작하는지 테스트한다.

## 2. SQLite 데이터베이스 테스트
- 테스트 환경에서는 인메모리 DB(`:memory:`)를 사용하여 변환 성공/실패 기록 저장, 차량번호/장비코드/기간별 필터 검색, 일일 통계 집계 쿼리를 검증한다.

## 3. 구현 완료 전 필수 검증 절차 (Definition of Done)
코드를 수정하거나 기능을 구현한 뒤에는 반드시 아래 3단계를 실행하여 통과를 확인한다:
1. **타입 검사**: `npm run typecheck` (`tsc --noEmit`) 에러 0건
2. **단위/통합 테스트**: `npm test` (`vitest run`) 전체 통과
3. **빌드 검증**: `npm run build` 정상 번들링 확인
